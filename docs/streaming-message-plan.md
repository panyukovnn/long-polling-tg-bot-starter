# Streaming Message Update — план реализации

Реализация постепенного отображения сообщения в Telegram: бот получает стрим токенов, накапливает их и периодически обновляет текущее сообщение через `editMessageText`.

## Задачи

- [x] Создать класс `StreamingMessageUpdater` в пакете `service` — объект, управляющий жизненным циклом одного стримящегося сообщения
- [x] Добавить метод `sendStreaming(Long chatId)` в `TgSender`, который отправляет начальное сообщение (например "▍") и возвращает `StreamingMessageUpdater`
- [x] В `StreamingMessageUpdater` реализовать:
  - `appendToken(String token)` — добавляет токен в буфер
  - Внутренний механизм батчинга: накапливает токены и обновляет сообщение через `editMessageText` не чаще чем раз в N миллисекунд (настраивается, по умолчанию ~1 сек для соблюдения rate limit Telegram)
  - `complete()` — финальное обновление с полным текстом
- [x] Добавить настройки в `TgBotProperties`: `streaming-update-interval-ms` (интервал обновления)
- [ ] Написать unit-тесты

## Ключевые моменты

- Telegram ограничивает частоту редактирования (~30 req/sec на бота, но на практике лучше не чаще 1 раз в секунду на сообщение)
- Используем `ScheduledExecutorService` для периодического flush буфера
- `StreamingMessageUpdater` будет потокобезопасным
